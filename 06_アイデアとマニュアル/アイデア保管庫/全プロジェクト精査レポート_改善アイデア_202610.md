# 全プロジェクト精査レポート＆改善アイデア集（2026年10月23日）

本ドキュメントは、ワークスペース内の全プロジェクト（計13カテゴリ・20以上のサブプロジェクト）をコード、Git管理状態、セキュリティ、パッケージ整合性の観点から徹底精査した結果と、今後の改善・発展アイデアをまとめた永続アーカイブです。

## 1. 最優先で解消すべき3大リスクと改善アイデア

### 【リスク1】Gitリモートへのトークン平文埋め込みと .gitignore 未設定による情報漏洩・著作権事故
- 現状の課題：
  ルートフォルダ全体が公開ホームページ（`Yuuchin-RNG-COL.git`）のリポジトリになっているにもかかわらず、`.gitignore` が存在しません。
  このまま誤って `git add .` や `git push` を実行すると、販売用の製品パッケージZIP、商用ツールの `.exe` 本体、さらにFF11から抽出したBGMデータ（`sandoria_bgm`、`last_number_bgm`、`latest_patch_bgm`）が全世界のGitHub Pages上に公開されてしまいます。

- 改善アイデア（自動防衛ゲート構想）：
  1. ホワイトリスト型の `.gitignore` をルートに配置し、公開Webサイトに必要なファイル（ルートのHTML/CSS/JS、`記事/`、`画像素材/images/`、`連携シミュレーター/`）以外の全フォルダ（`01_`〜`09_`、`comment-viewer-v2`、BGMフォルダ等）をGit追跡対象から完全遮断する。
  2. Gitの `pre-commit` フックに自動監査スクリプトを組み込み、`.exe`、`.zip`、`.bgw`、APIキー、アクセストークンが含まれている場合はコミット自体を自動ブロックする仕組みを導入する。

### 【リスク2】複数箇所に分裂・重複したプロジェクトの「正本（シングルソース）」化
- 現状の課題：
  - お給仕コメビュ系が4箇所に分散（`comment-viewer-v2`、ルートの `comment-viewer` ジャンクション、`01_配信ツール類/コメビュ版お給仕翻訳`、さらに `comment-viewer-v2/comment-viewer/overlay.html` の不要な入れ子）。
  - 連携シミュレーターが3箇所に存在し、ルートと `preview-v2` は同一だが、`01_配信ツール類/連携シミュレーター/script.js` だけ古いバージョンのまま放置されている。
  - ホームページ次世代版も `v2`、`preview-v2`、`07_システム開発・一時作業/preview-v2` の3箇所に重複している。
- 改善アイデア（モノレポ整理・アーカイブ化）：
  1. 各プロダクトの「正本ディレクトリ」を1つだけに定め、旧バージョンや実験ブランチは `07_システム開発・一時作業/archive/` へ一括退避または削除する。
  2. 公開用と開発用で同じコードを使う場合は、コピーではなくビルドスクリプトまたはシンボリックリンクで同期させ、古いコードへの誤修正をゼロにする。

### 【リスク3】販売・配布ツールのセキュリティ基準（CORS・Webセキュリティ無効化）の近代化
- 現状の課題：
  ローカルサーバー（`server.ps1`、`auditor_server.py`、`hallucination_monitor.py`、`fact_monitor.py`）の計10ファイルでCORSオリジン全許可が設定されており、コメビュや販売用配信コントロールセンターの起動バッチ計7ファイルで `--disable-web-security` が使用されています。

- 改善アイデア（セキュア・ローカルサーバー共通基盤）：
  1. 全ツール共通で使える「安全なローカルサーバー共通モジュール（PowerShell版 / Python版）」を1つ作成する。
  2. オリジン許可を `http://127.0.0.1` と `http://localhost` のみに厳格化し、外部API通信はローカルサーバー側でプロキシ中継させることで、ブラウザの `--disable-web-security` フラグを完全に撤廃する。これにより購入者環境でのセキュリティ警告やウイルス誤検知リスクを根本から解消できる。
