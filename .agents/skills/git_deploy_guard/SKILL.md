# デプロイ前ガードスキル

## このスキルの目的

過去に「下書き」「Draft」「検証用」などの文言が残ったままデプロイしてしまうミスが発生した。
このスキルは `git commit` または `git push` を行う前に、必ず以下のチェックリストを実行して公開事故を防ぐための手順を定める。

---

## チェック対象ファイルの特定

デプロイ前チェックの対象は、今回の変更で `git add` したすべてのファイル。
以下のコマンドで確認する：

```powershell
git diff --cached --name-only
```

---

## 必須チェックリスト（全項目クリアするまでコミット禁止）

### チェック1：下書き・仮置き文言の残存確認

以下のキーワードがファイル内に存在しないかを検索する：

```powershell
git diff --cached | Select-String -Pattern "下書き|Draft|draft|検証用|テスト中|TODO|FIXME|WIP|（仮）|（temp）"
```

引っかかった場合は該当箇所を修正してから再度チェックする。

### チェック2：日英ファイルの対称性確認

日本語版（`index.html`、`article.html` 等）を変更した場合は、対応する英語版（`index_en.html`、`article_en.html` 等）にも同様の変更が反映されているかを確認する。

逆も同様。英語版を変更したら日本語版の確認を行う。

確認方法：変更したファイル名を元に、対応する `_en` ファイルまたは非`_en` ファイルを `view_file` で開いて目視確認する。

### チェック3：開発者向けコードの残存確認

```powershell
git diff --cached | Select-String -Pattern "console\.log|debugger|alert\("
```

意図的に残す `console.warn` や `console.log` がある場合（コメビュのデバッグログ等）は除外してよいが、一時的なデバッグ用途のものは削除する。

### チェック4：リンク切れの簡易確認

新しく追加したリンク（`href=`、`src=`）が存在するファイルを参照しているかをざっくり確認する。
特に記事のリンク紐付けを行った場合は、リンク先ファイルが実際に存在するかを確認する。

### チェック5：手動専用ファイルの非改変確認

以下のファイルが `git diff --cached` に含まれていないことを確認する：

- `管理ロジック_手動専用.js`
- `管理画面_手動専用.html`
- `コメビュ版お給仕起動_手動専用.bat`

含まれていた場合は即座に `git restore --staged <ファイル名>` でステージングから外す。

---

## What's New への掲載チェック

新しい記事や機能をデプロイする場合は、`index.html` および `index_en.html` の「What's New」セクションに掲載エントリが追加されているかを確認する。

---

## チェック完了後の報告フォーマット

すべてのチェックが完了したら、以下の形式でゆうさんに報告してからコミット・プッシュを実行する：

```
デプロイ前チェック完了：
- 下書き文言：なし
- 日英対称性：確認済み（または対象外）
- デバッグコード：なし（または意図的残存あり・理由：〇〇）
- リンク確認：問題なし
- 手動専用ファイル：変更なし
```

---

## 過去の教訓（再発防止メモ）

- 記事タイトルや見出しに「（下書き）」が残ったままデプロイしてしまったことがある
- 日本語版を更新して英語版の更新を忘れたことがある
- 上記2件はいずれも「確認を省略した」ことが原因。このチェックリストは省略しない
