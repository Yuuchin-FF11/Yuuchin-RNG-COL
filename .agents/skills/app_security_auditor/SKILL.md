# 販売向け品質＆セキュリティ監査スキル

## このスキルの目的
製品・アプリを外部向けに販売・公開・配布する際、セキュリティホールや購入者側PCでの起動トラブル（サポートコストの増大）を未然に防止するための品質監査を実施する。

## 発動契機
- ツールやアプリ（`01_配信ツール類` やその他の配布用スクリプト）の開発完了時
- 配布・販売パッケージの作成前
- 「セキュリティチェックをして」「販売前チェックをして」と指示されたとき

## 監査チェックリスト

### 1. 機密情報・APIキーの保護
- コード内にOpenAI、Gemini、YouTube等のAPIキーやパスワードが平文で直接ハードコードされていないか。
- `.env` や外部設定ファイルに分離され、`.gitignore` でリポジトリ公開対象から除外されているか。

### 2. セキュリティ設定の厳格性
- Chrome等の起動オプションに `--disable-web-security` や `--disable-features=IsolateOrigins` 等の危険なフラグが含まれていないか。
- ローカルサーバー（PowerShellやNode.js等）で、不要・安易な `Access-Control-Allow-Origin: *` が設定されていないか。

### 3. 購入者・ユーザー環境でのエラー耐性（サポートコスト削減）
- 【PowerShell実行ポリシー】:
  - `.ps1` スクリプトを配布する場合、購入者のPCが `Restricted` ポリシーであっても起動できるよう、`-ExecutionPolicy Bypass` を付与したバッチファイル（`.bat`）起動ランチャーが用意されているか。
- 【外部ソフトウェア依存（VOICEVOX等）】:
  - VOICEVOX等の外部プロセスに依存するツールの場合、未起動時にフリーズせず「VOICEVOXが起動していません。起動してください」という明確な日本語ガイダンスが表示されるか。
- 【ポート競合対策】:
  - 指定ポート（例: 8080, 50021等）が使用中の場合にクラッシュせず、別ポートを試行するか親切なエラー通知が出るか。

### 4. 非公式API・ライセンス確認
- サービス提供元の利用規約に反する非公式APIのスクレイピングやリバースエンジニアリングを行っていないか。公式APIまたは安全な代替手段を採用しているか。

## 監査結果の出力形式
監査完了後は、以下のフォーマットで報告する：
・【適合（合格項目）】
・【要修正（高リスクな問題）】
・【推奨改善（サポートコスト削減のための提案）】
