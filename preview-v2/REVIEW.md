このドキュメントは、現行サイトのデザインやスマホ表示、アクセシビリティを劇的に改善した「比較検討用V2（preview-v2）」の変更内容と検証結果、および将来的な差し替え手順をまとめたものです。

## 1. 作成したファイル一覧

すべての新しい実装は、プロジェクト直下の「preview-v2/」内に完全分離して作成されました。

- preview-v2/index.html
  トップページの構成およびセクション順序を全面的に見直した新しいメインHTMLです。
- preview-v2/styles.css
  セクションごとの背景グラデーション濃淡設定や、スマホ表示の最適化、prefers-reduced-motionに対応したスタイルシートです。
- preview-v2/script.js
  フェードインアニメーションの制御、更新履歴リストの自動抽出制御、および外部AIチャットの無効化（ローカルダミー応答化）を行うメインスクリプトです。
- preview-v2/article.html
  スマホでの本文幅の劇的改善、パンくずリストや各種メタ情報の表示領域追加、アコーディオン式のスマホ目次、Markdownの前処理レンダリングを実装した新しい記事用HTMLです。
- preview-v2/共通コンポーネント.js
  目的別ナビゲーションメニューの整理、通常のbuttonタグを用いたアクセシブルなスマホハンバーガーメニューの実装、および管理者システムの無効化を行った共通JSです。
- preview-v2/連携シミュレーター/index.html
  レスポンシブかつ1列表示に対応し、「さらに表示」ボタンを追加したシミュレーターのメインHTMLです。
- preview-v2/連携シミュレーター/style.css
  スマホでの1列レイアウト化、セレクトボックスの文字省略防止を盛り込んだシミュレーター用のスタイルシートです。
- preview-v2/連携シミュレーター/script.js
  探索結果を最初に上位のおすすめ3件にバッジを付与して際立たせ、初期結果を15件に制限して「さらに表示」で追加ロードするページング機能を実装したシミュレーターの制御スクリプトです。計算ロジック自体は現行版と100%一致しています。
- preview-v2/IMPLEMENTATION_PLAN.md
  変更対象と実装手順を記録した実装計画書です。
- preview-v2/REVIEW.md
  このレビュー報告書です。

## 2. 現行版から変更した点

### ナビゲーションとスマホメニューの改善
- 読者の目的に応じた分類へメニュー項目を再整理しました。
  【整理されたメニュー項目】
  ・初心者・復帰
  ・狩人・コルセア装備
  ・コンテンツ攻略
  ・金策・便利情報
  ・連携ツール
  ・配信・プロフィール
- スマホ用ハンバーガーメニューボタンを、従来のdivタグによる自作トグルから通常の「button」タグに変更し、タップ領域を44px以上確保しました。
- 「aria-label」「aria-expanded」「aria-controls」を設定し、メニューの開閉状態がスクリーンリーダー等の支援技術へ正しく伝わるようにしました。
- キーボード操作（Tabキーでのフォーカス遷移、Escapeキーによるメニューの閉じ動作）およびメニュー外クリックによる閉じ動作に対応しました。
- 開閉処理イベントの多重登録を排除し、状態の相殺バグを完全に修正しました。閉じているメニューは「visibility: hidden」によって支援技術から適切に隠蔽されます。

### トップページ（index.html）の構成改善
- 読者のニーズに沿ったセクション順序へ全面的に組み替えました。
  【並び順】
  1. コンパクトなヒーローセクション
  2. 読者別の3つの入口（完全新規・復帰者・現役エンド）
  3. 目的別カテゴリ
  4. 最新更新3〜5件（「更新履歴をすべて見る」ボタンで最下部へスクロール）
  5. おすすめ記事（特に注目すべき代表的ガイド3選）
  6. 作者のプレイスタイル
  7. YouTube・配信・ヴァナ生活
  8. 更新履歴全文（最下部のスクロール可能なエリア）
- ヒーローセクションをコンパクトに再設計し、見出し・説明文・最優先の入口ボタンがスクロール不要でファーストビューに収まる構成にしました。
- 従来の巨大な24周年記念バナー画像をヒーロー下部に移動し、「24周年記念カードバナー」として丁寧に再配置しました。
- セクションごとに背景のグラデーションや濃淡（bg-alt-1、bg-alt-2）を設定し、現行版の青緑一色という単調さを解消して、読みやすさと高級感を持たせました。
- prefers-reduced-motionに対応し、OS側で動きを減らす設定にしているユーザーにはパーティクル背景やCSSアニメーションの動きを自動停止させます。

### スマホ記事ページ（article.html）の表示改善
- 390px幅のスマホで本文幅が162pxまで狭くなっていたレイアウトバグを解消しました。外側余白を左右16px、カード内余白を左右16px〜20px、本文余白を0pxとすることで、390px端末で最低300px以上の本文可読領域を確保しました。
- 文字サイズと行間を、スマホ端末で最も読みやすいとされるバランスに調整しました。
  ・H1：26px（行間1.35）
  ・H2：22px（行間1.4）
  ・本文：16px（行間1.75）
- 横スクロールの発生を完全に抑止しました。幅の広いテーブル（装備表など）には横スクロール可能なラッパーを自動適用し、全体のレイアウト崩れを防ぎます。
- 固定の「ページ上部へ」ボタンの配置とサイズを調整し、本文を覆って邪魔しないよう右下にコンパクトに配置しました。
- 記事上部に「パンくずリスト」、および「対象読者」「この記事の到達目標」「前提条件」「更新日」を一覧表示するメタボックスを追加しました。
- スマホ閲覧時のみ、アコーディオンのように開閉できる「折りたたみ式目次（TOC）」を本文の先頭付近に配置しました。
- 記事の末尾に「同カテゴリの他記事（最大3件）」を魅力的なカードとして動的に挿入し、カテゴリ一覧やトップへ戻るナビゲーション導線を強化しました。
- Markdownパーサーの前処理を実装し、現行のMarkdownファイルを修正することなく、「---」「###」「[!NOTE]」「[!TIP]」「[!CAUTION]」などの記法を美しい警告枠やレイアウトへ自動変換します。
- 簡易サニタイズ処理を追加し、XSS（クロスサイトスクリプティング）対策を強化しました。

### 連携シミュレーターの改善
- スマホ表示時、横並びの2列から1列レイアウトへ自動で切り替えるようにしました。
- 武器選択セレクトボックスの幅を広げ、スマホ画面でも武器名（例：「格闘 (Hand-to-Hand)」など）が省略されず最後まで綺麗に読めるようにしました。
- 探索結果の初期表示数を制限しました。結果が100件あった場合に一気に縦に並べてブラウザをフリーズさせるのを防ぐため、最初に「おすすめの3件」を目立たせて表示し、初期表示全体は15件に抑え、下部の「さらに結果を表示する」ボタンをクリックするごとに追加で15件ずつ読み込む仕組みを導入しました。
- シミュレーションの計算ロジックやソート基準は変更していないため、計算結果は現行版と100%一致します。

### プライバシーと外部通信の無効化（V2プレビュー版限定仕様）
- Supabase接続およびGmail通知用GASの通信を無効化し、コメント送信はブラウザのlocalStorageに一時保存して擬似的に動作させる設計にしました。
- アクセスログのGAS送信（logAccess関数）をダミー化し、外部送信を行わないようにしました。
- 管理者認証のGAS通信をダミー化し、パスワード送信を行わずに説明を表示するようにしました。
- Gemini APIによる外部AIチャット機能への通信を無効化し、モグボットへの質問入力時は「こちらはV2プレビュー版のためAIチャットは無効化されています」とダミー応答を返すセキュアな仕様にしました。

## 4. 現行版に残っている問題

比較検証を通じて浮き彫りになった、現行版（本番公開版）に残存している主要な課題は以下の通りです。

- スマホ幅（390px）において、複数の入れ子コンテナ（.article-container, .article-card, .markdown-body）の余白が累積し、実効本文幅が約162pxまで圧縮されてしまい、日本語が数文字ごとに改行されて極めて読みにくい状態になっている。
- ハンバーガーメニューがdiv要素で作られており、キーボード操作やスクリーンリーダー等の支援技術に対応していない。また、JSイベントの多重登録により開閉が相殺される不具合がある。
- トップページのファーストビューに巨大な24周年画像と長文が居座り、初心者が求める攻略への導線（入口）がスクロールしないと見えない。
- 記事内のGitHub Alert記法（[!NOTE]、[!CAUTION]など）がパーサー未対応のため、生のテキストとしてそのまま画面に露出している。
- 連携シミュレーターでスマホ表示時に武器名が枠外にはみ出して省略され、検索結果が100件あると一括描画でスクロールが重くなる。

## 8. 将来採用する場合の差し替え手順案

比較の結果、V2版の採用を決定した場合は、以下の手順で現行版と安全に差し替えることができます。

- 1. 万が一に備え、現行のトップレベルにある「index.html」「styles.css」「script.js」「article.html」を「backup-v1/」などの一時フォルダに退避させます。
- 2. 「preview-v2/」配下の以下のファイルを、プロジェクトのルートディレクトリにコピー（上書き）します。
     ・index.html
     ・styles.css
     ・script.js
     ・article.html
- 3. 「preview-v2/共通コンポーネント.js」を「画像素材/js/共通コンポーネント.js」に上書きコピーします。
- 4. 「preview-v2/連携シミュレーター/」配下のファイルを、ルートの「連携シミュレーター/」配下に上書きコピーします。
- 5. 差し替えた各ファイルの script タグや CSS 読み込みリンクなどのファイルパス（例：`../画像素材` や `共通コンポーネント.js` のパス）を、ルートディレクトリの構造に合わせて微調整（`../` を `画像素材/` に書き換える等）します。
- 6. 必要に応じて、SupabaseやGASの通信設定を本番用に再有効化します。
- 7. テスト環境でリンク切れやパス崩れがないか確認し、問題がなければコミットおよびデプロイを行います。

## 10. 本シミュレーター＆サイトの導入価値（初心者向け解説）

### このツールを導入することで、具体的にどのような作業が楽になるのか（導入メリット）
FF11は連携属性の仕様が非常に複雑で、どのウェポンスキル（WS）同士を組み合わせれば狙った連携が発動するのかを調べるには、何十種類もあるWSの属性データを毎回用語辞典で調べて手動で計算する必要がありました。
本シミュレーターを導入することで、自分が使いたい武器種を2つ選ぶだけで、数秒で可能なすべての連携ルートを自動計算して一覧表示します。これにより、実戦中の構成に合わせた連携ルート構築の手間がほぼゼロになり、戦略立案が劇的にスピードアップします。

### このツールを使うと、具体的にどのようなことができるのか（機能の直感的な要約）
・「トス」と「シメ」で使う武器を選ぶだけで、発動可能なWSの組み合わせと順番を自動で逆引き検索します。
・多段連携（3連携〜最長6連携）に対応し、タイムライン形式でコンボの順番とタイミングがひと目でわかります。
・発動した連携に対して、どの魔法属性でマジックバースト（MB）を狙えるかを一目でわかるようにエレメントバッジで表示します。
・お気に入りの検索条件を保存できるため、自分のジョブ構成に合わせたルートを一瞬で呼び出せます。

### 他の生成AIツール等と連携して活用する方法（AIシナジー）
例えば、ChatGPTやClaudeなどの生成AIチャットツールに対して、
「連携シミュレーターで、片手剣から短剣への3手連携で光を発生させるルートが 〇〇 ➔ 〇〇 ➔ 〇〇 と出ました。このコンボを実戦のオデシー・ジェールで決めるためのマクロの書き方と、各WS間の待機フレーム数を教えてください」
と質問することで、シミュレーターの結果に基づいた超具体的なマクロテンプレートや実戦的なアドバイスをAIから一瞬で引き出すことができます。
シミュレーターで機械的なルートを探し、詳細なマクロの組み立てや戦術相談をAIに投げるという2ステップを踏むことで、攻略効率を極限まで高めることが可能です。
