# ファクト・スキャナー 監視サーバー障害レポート

## 発生した問題
「監視サーバー起動.bat」をダブルクリックすると、PowerShellのコンソールに「自動監視サーバーが起動しました」と表示されるが、ブラウザで localhost:8080 にアクセスすると「ERR_CONNECTION_REFUSED」（接続拒否）となり、サーバーが実際には動いていない状態だった。

## 原因の特定
ログファイル「fact_monitor.log」を確認したところ、PowerShellのパースエラー（構文解析エラー）が記録されていた。原因は2つ。

### 原因1：PowerShellに存在しない構文「elif」の使用
fact_monitor.ps1 の139〜142行目で、Pythonの条件分岐構文である elif が使われていた。PowerShellには elif は存在せず、正しくは elseif を使う必要がある。

```diff
 if ($ext -eq ".png") { $contentType = "image/png" }
-elif ($ext -eq ".jpg" -or $ext -eq ".jpeg") { $contentType = "image/jpeg" }
-elif ($ext -eq ".gif") { $contentType = "image/gif" }
-elif ($ext -eq ".css") { $contentType = "text/css" }
-elif ($ext -eq ".js") { $contentType = "application/javascript" }
+elseif ($ext -eq ".jpg" -or $ext -eq ".jpeg") { $contentType = "image/jpeg" }
+elseif ($ext -eq ".gif") { $contentType = "image/gif" }
+elseif ($ext -eq ".css") { $contentType = "text/css" }
+elseif ($ext -eq ".js") { $contentType = "application/javascript" }
```

### 原因2：改行コードがLFのみだった
ファイルの改行コードがUnix形式の「LF」のみになっていた。Windows PowerShell 5.1では、LFのみの改行だと try { } catch { } のような複数行にまたがるブロック構文のパースに失敗するケースがある。「CRLF」に変換し、UTF-8 BOM付きで保存し直すことで解決した。

この2つのエラーが組み合わさった結果、スクリプト全体がパースに失敗し、HTTPリスナーが一切起動できない状態になっていた。バッチファイル側は「起動コマンドを実行した」というところまでしか見ていないため、実際にはサーバーが動いていなくても「起動しました」と表示されていた。

## 根本的な対策：PowerShellからPythonへの移行
上記のエラーを修正すればPowerShell版も動作するが、そもそもHTTPサーバーをPowerShellで書くこと自体に以下のリスクがあるため、Python版への移行を実施した。

・PowerShellの HttpListener はシングルスレッドで、重い処理でブラウザがフリーズする
・構文の罠が多い（elif vs elseif、改行コード依存のパースエラーなど）
・日本語パスとの相性問題が起きやすい
・エラー発生時にサイレントに停止してしまい、原因特定が困難

### 移行で行ったこと

#### Python 3.12.10 のインストール
・winget install Python.Python.3.12 でインストール
・以前は「Pythonが動かない」と思われていたが、実際はWindowsのMicrosoft Storeリダイレクト用スタブしかなく、本物のPythonが入っていなかっただけだった

#### fact_monitor.py の新規作成
・PowerShell版と完全互換のAPIを提供するPython版監視サーバー
・Python標準ライブラリのみで動作（外部パッケージ不要）
・MIMEタイプの対応を拡充（SVG、WebP、フォントファイル等にも対応）
・ディレクトリトラバーサル対策を追加（セキュリティ向上）
・ポーリングログの抑制（コンソールが溢れない）

#### 監視サーバー起動.bat の更新
・PowerShell呼び出しからPython呼び出しに変更
・py ランチャーを優先し、なければ python にフォールバック
・サーバーは別ウィンドウで起動する構成
・バッチファイル自体はASCII文字のみで記述（日本語のエンコーディング問題を回避）

## バッチファイル更新時に追加で発生した問題
バッチファイルの書き換え時に、以下の追加問題が発生し対処した。

・cmd.exeはShift-JIS（CP932）でバッチファイルを解釈するため、UTF-8で保存されたバッチファイル内の日本語が文字化けし、コマンド自体が壊れた
・日本語テキスト内の半角括弧 () が、バッチファイルの if (...) ブロック構文の括弧と衝突し、パースエラーを引き起こした
・最終的に、バッチファイルの表示メッセージをすべて英語（ASCII文字のみ）にすることで、エンコーディング問題を根本的に回避した

## 現在の状態
「監視サーバー起動.bat」をダブルクリックすると、以下の動作が正常に行われる。

・ポート8080の重複プロセスがあれば自動終了
・Pythonの自動検出（py ランチャー優先）
・Python版監視サーバーが別ウィンドウで起動
・ブラウザが自動で http://localhost:8080/ を開く
・ファクト・スキャナーのUIが正常に表示され、ファイル変更の自動監視が機能する
