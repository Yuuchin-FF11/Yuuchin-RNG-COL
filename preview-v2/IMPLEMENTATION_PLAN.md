# 比較検討用V2（preview-v2）実装計画

この計画書は、現行のFF11攻略サイトの良さを残しつつ、デザイン、情報設計、スマホ表示、およびアクセシビリティを劇的に改善した比較検討用のV2バージョンをプロジェクト直下の「preview-v2/」ディレクトリ内に完全分離して作成するためのものです。

現行のファイルや記事、画像、シミュレーターなどの資産は一切変更せず、完全に維持したまま作業を進めます。

---

## ユーザーレビュー要求事項

V2実装を進めるにあたり、以下の設計方針についてご確認をお願いいたします。

1. 外部通信（Supabaseコメント、Google Apps Scriptログ送信、Gemini APIチャット）の無効化：
   プライバシーと外部通信のルールに基づき、V2ではこれらの外部通信処理を無効化します。これに伴い、AIチャットUIやコメント投稿フォームは画面上には残しますが、動作はローカルダミー応答とするか、または無効化状態であることを示すメッセージを表示します。

2. プレースホルダー画像：
   ゲーム内の実画面画像が不足している場合、ハルシネーション（偽画像の生成）を防ぐため、指定のテキストプレースホルダー（例：「画像準備中：エミネンス・レコードのメニュー画面」）を配置します。

## 変更対象ファイル一覧

すべての新規作成・編集ファイルは「preview-v2/」ディレクトリ配下に配置します。

- 【NEW】preview-v2/index.html (現行のindex.htmlをベースに構成変更)
- 【NEW】preview-v2/styles.css (現行のstyles.cssをベースにセクション背景の濃淡調整など)
- 【NEW】preview-v2/script.js (現行のscript.jsをベースに外部通信無効化とスクロールアニメ調整)
- 【NEW】preview-v2/article.html (現行のarticle.htmlをベースにスマホレイアウト・ナビ導線・前処理追加)
- 【NEW】preview-v2/共通コンポーネント.js (ヘッダーの読者目的別整理、スマホメニューのアクセシビリティ対応)

- 【NEW】preview-v2/IMPLEMENTATION_PLAN.md (プロジェクト内の計画記録)
- 【NEW】preview-v2/REVIEW.md (成果物・確認結果等のまとめ)

## 実装手順

### ステージ 1：環境準備とファイルコピー
- 1. プロジェクト直下に「preview-v2」および「preview-v2/連携シミュレーター」ディレクトリを作成します。
- 2. 現行の「index.html」「styles.css」「script.js」「article.html」を「preview-v2/」にコピーします。
- 3. 「画像素材/js/共通コンポーネント.js」を「preview-v2/共通コンポーネント.js」としてコピーします。
- 4. 「連携シミュレーター/」配下の「index.html」「script.js」「style.css」を「preview-v2/連携シミュレーター/」配下にコピーします。
- ※ 記事Markdownや画像、原本シミュレーター等のファイルは一切変更しません。

### ステージ 2：共通ナビゲーションとスマホメニューの改善
- 1. 「preview-v2/共通コンポーネント.js」のヘッダーメニューを、以下の読者の目的が分かる分類に整理します。
     - 初心者・復帰
     - 狩人・コルセア装備
     - コンテンツ攻略
     - 金策・便利情報
     - 連携ツール
     - 配信・プロフィール
- 2. スマホ用メニューボタンを「div」から通常の「button」タグに変更し、タップ領域を44px以上確保します。
- 3. 「aria-label」「aria-expanded」「aria-controls」などのアクセシビリティ属性を動的に制御する処理を追加します。
- 4. キーボード操作（Tabキー、Escapeキーで閉じるなど）やメニュー外クリックでのクローズ処理を実装します。二重登録によるイベントの相殺を防ぎます。
- 5. 閉じているメニューが支援技術から適切に隠れるように「visibility: hidden」や「display: none」を組み合わせます。

### ステージ 3：トップページの構成改善 (preview-v2/index.html)
- 1. トップページのセクション順序を以下のように並び替えます。
     - 1. コンパクトなヒーローセクション
     - 2. 読者別の3つの入口（完全新規・復帰者・現役エンド）
     - 3. 目的別カテゴリ
     - 4. 最新更新3～5件（「更新履歴をすべて見る」ボタンで展開・別画面へ）
     - 5. おすすめ記事
     - 6. 作者のプレイスタイル
     - 7. YouTube・配信・ヴァナ生活
     - 8. 更新履歴全文（折りたたみアコーディオンまたは展開エリア）
- 2. ヒーローセクションをコンパクト化し、最初の画面内に見出し「FF11遠隔ジョブに全振りした タルの日常」、説明文、最優先の入口ボタンがすべて収まるようにレイアウトを再設計します。
- 3. 24周年バナー画像をヒーローセクションから下部へ移動し、「24周年記念」カードとして下部にバナー形式で配置します。
- 4. セクションごとに背景のグラデーションや濃淡を変化させ、青緑一色の単調な背景から、メリハリのあるモダンなデザインへとブラッシュアップします。
- 5. prefers-reduced-motion に対応し、視覚効果を減らす設定のユーザーに対してはパーティクル背景やCSSアニメーションの動きを停止させます。

### ステージ 4：スマホ記事ページの表示改善 (preview-v2/article.html)
- 1. 390px幅のデバイスにおいて本文幅が狭くならないよう、余白を調整します（外側余白左右16px、カード内余白左右16px～20px、本文幅最低300px確保）。
- 2. フォントサイズと行間の設定を読みやすく最適化します。
     - H1：26～30px、行間1.3～1.45
     - H2：22～25px
     - 本文：16～18px、行間1.7～1.9
- 3. 横スクロール（overflow-x）の発生を防ぎます。固定の「ページ上部へ」ボタンが本文を覆って邪魔しないよう、右下に控えめに配置します。
- 4. 記事ページの上部に「パンくずリスト」、および「対象読者」「この記事の到達目標」「前提条件」「最終更新日表示領域」を追加します。
- 5. スマホ表示時、目次（TOC）をアコーディオン状に折りたためるコンポーネントに変更します。
- 6. 記事の末尾に「次に読む記事」「同カテゴリの記事」「カテゴリ一覧へ戻る導線」を静的または動的に追加します。
- 7. Markdownパーサーの前処理を実装し、既存のMarkdownを修正せずに、「---」「###」「[!CAUTION]」「[!TIP]」「[!NOTE]」などの特殊記法を安全なHTML（警告ボックスなど）へ変換します。XSS対策（DOMPurifyに代わる簡易サニタイズ等）を施します。

### ステージ 5：連携シミュレーターのレスポンシブ改善 (preview-v2/連携シミュレーター/)
- 1. スマホ表示（768px未満）の際、2列グリッドから1列レイアウトに変更します。
- 2. セレクトボックスの横幅を十分に取り、武器名（例：「格闘 (Hand-to-Hand)」など）が省略されずに全て読めるようにします。
- 3. 探索結果の初期表示件数を制限します。最初に「おすすめ3件」を上位表示し、初期状態では10〜20件を表示します。下部に「さらに表示」ボタンを設置し、クリックするごとに追加で結果を表示する仕組みにします（100件を最初から一括表示しない）。
- 4. 計算結果が現行版と100%一致することを確認します（計算ロジック自体は一切書き換えず、表示制御のみを追加します）。

### ステージ 6：プライバシー保護と外部通信の無効化
- 1. コメント投稿時のSupabase送信、およびGmail通知用のGAS fetch処理を無効化し、ローカルで成功メッセージを返すダミー仕様にします。
- 2. 管理者ダッシュボード認証時のパスワード送信 fetch 処理を無効化します。
- 3. Gemini APIのキー入力・保存および外部SDKの読み込みを停止します。
- 4. アクセス時のロガー（logAccess関数）のGAS通信を停止します。

## 検証計画

### 画面幅別表示検証
以下の画面幅で表示崩れ、横スクロール、文字の不自然な折り返しがないか検証します。
- 1. 390px × 844px（一般的なスマートフォン）
- 2. 768px × 1024px（タブレット）
- 3. 1440px × 900px（PC標準）
- 4. 1920px × 1080px（フルHD）

### テスト項目
- 1. スマホでのハンバーガーメニュー開閉動作の検証（Escapeキー、背景クリックでの閉じ動作確認、キーボードフォーカスの遷移確認）。
- 2. 記事ページのMarkdownレンダリング結果の確認。前処理による「[!NOTE]」等のデザイン反映と、本文幅の確認。
- 3. 連携シミュレーターの動作確認。初期結果が制限され、「さらに表示」で追加ロードされること。現行版の計算結果と一致することの突合。
- 4. ブラウザの開発者ツールコンソールにエラーが出ていないことの確認。
- 5. V2配下のリンクパスが正しく「preview-v2/」内を指していることの確認。

### 現行ファイルの安全性確認
- 修正前後で `git diff` を実行し、プロジェクト直下の現行ファイル（`index.html`, `styles.css`, `script.js`, `article.html`, `連携シミュレーター/*` 等）に変更が一切加えられていないことを物理的に確認します。
