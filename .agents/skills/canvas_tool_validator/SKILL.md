# Canvas・Webツール品質＆描画安全性監査スキル

## このスキルの目的
HTML5のCanvas要素を活用した画像合成・編集ツール（サムネイル作成ツールやバナー生成ツール等）において、描画のズレ、Retinaディスプレイでの画質劣化（ぼやけ）、画像の読み込み不良、ダウンロード保存時のCORSエラーを未然に防止する。

## 発動契機
- `04_サムネイル作成ツール` 内のHTML/JSファイル、またはCanvas描画を扱うコードの作成・修正時
- 画像生成・トリミング・合成機能の改修時
- 「Canvasの描画をチェックして」「サムネツールの動作確認をして」と指示されたとき

## 監査チェックリスト

### 1. 高DPI（Retinaディスプレイ等）対応
- `canvas.width` / `canvas.height`（描画バッファ解像度）と `canvas.style.width` / `canvas.style.height`（CSS表示サイズ）を混同していないか。
- `window.devicePixelRatio` を取得し、描画コンテキストに対して `ctx.scale(dpr, dpr)` 等の解像度補正を行い、文字やベクター描画がぼやけない設計になっているか。

### 2. 画像・アセットの読み込み完了待機（非同期保証）
- `new Image()` で読み込む画像を、`onload` イベント完了前に `ctx.drawImage()` で描画しようとしていないか。
- 複数の画像や背景画像を合成する場合、`Promise.all` 等を用いてすべての画像が読み込み完了した後に一括描画する構造になっているか。

### 3. フォント読み込みの同期とフォント化け防止
- Google Fontsやローカルフォントを使用する際、フォントデータの読み込み完了前に文字を描画してブラウザ標準フォントで固定化（化け）していないか。
- `document.fonts.ready` 等でフォント適用完了を待ってから再描画する処理が入っているか。

### 4. CORS汚染とデータエクスポートの安全性
- Canvasから画像をダウンロード・保存する処理（`canvas.toDataURL()` や `canvas.toBlob()`）において、「Tainted canvases may not be exported」エラー（CORS違反）が発生しない構成になっているか。
- ユーザーがアップロードした画像（ローカル画像）は `FileReader` を用いてDataURLまたはBlob URLとして安全に読み込んでいるか。
- 外部URL画像を使用する場合は `img.crossOrigin = "anonymous"` が設定され、かつサーバー側でCORSが許可されているか。

### 5. 元画像解像度の維持と座標計算の厳密性
- プロジェクトルールの「画像ファイルの物理サイズの確認徹底」および「座標計算や範囲指定の厳密な特定」に準拠しているか。
- 画面上の表示サイズで座標を計算せず、画像の元サイズ（naturalWidth / naturalHeight）を基準に正確なピクセル座標・トリミング範囲を算出しているか。

## 監査結果の出力形式
監査完了後は、以下のフォーマットで報告する：
・【合格項目（描画・出力が安全な点）】
・【重大リスク（ぼやけ・CORSエラー・読み込み失敗のリスク）】
・【改善推奨（UX向上や描画高速化のための提案）】
