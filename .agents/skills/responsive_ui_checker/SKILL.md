# モバイル表示・レスポンシブUI監査スキル

## このスキルの目的
スマートフォンやタブレットでの閲覧・操作を前提としたWebサイトやPWAアプリ（連携シミュレーター、FF11攻略記事、製品スライド等）において、横スクロールの発生（レイアウト崩れ）、ボタンのタップしにくさ、文字の視認性低下を未然に防止する。

## 発動契機
- `連携シミュレーター`、`記事` 内のHTML/CSS、または製品解説スライド等のWebページ作成・修正時
- レスポンシブレイアウトやメディアクエリの追加・変更時
- 「スマホ表示を確認して」「レスポンシブ崩れをチェックして」と指示されたとき

## 監査チェックリスト

### 1. 水平スクロール（横はみ出し）の防止
- スマートフォンの一般的な画面幅（375px〜430px）において、横スクロールバーが発生する要因がないか。
- `width: 600px` などの固定幅指定がメディアクエリ外で無防備に書かれていないか（`max-width: 100%` や `box-sizing: border-box` の適用確認）。
- 画像やテーブル、埋め込み動画（iframe）が親要素の横幅を突き破っていないか。
- `overflow-x: hidden` を安易に `body` に適用して誤魔化すのではなく、根本原因となるはみ出し要素を解消しているか。

### 2. Viewport設定の整合性
- HTMLの `<head>` 内に適切なビューポート設定が存在するか。
  `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
- `user-scalable=no` などの極端な拡大禁止設定で、アクセシビリティを損なっていないか。

### 3. タップターゲットのサイズと余白
- スマートフォンの親指操作で押し間違えないよう、ボタンやリンクのタップ領域が十分確保されているか（推奨: 最小 44px × 44px の領域）。
- ボタン同士が近接しすぎて誤タップを誘発する配置になっていないか（適切な `gap` や `margin` の確保）。

### 4. モバイル文字サイズと入力フォーム
- スマートフォン表示時の本文文字サイズが極端に小さくないか（14px〜16px以上を維持しているか）。
- iOS Safariでのフォーカス時ズーム暴発を防ぐため、テキスト入力欄（`input`, `textarea`, `select`）のフォントサイズが16px以上に保たれているか。

### 5. PWA・Webアプリとしての操作性（該当する場合）
- PWA対応アプリ（連携シミュレーター等）において、`manifest.json`、`theme-color`、およびアイコン設定がモバイル端末のホーム画面追加に対応しているか。
- モバイルブラウザ特有のアドレスバー伸縮による `100vh` のレイアウト崩れ対策（`dvh` や `svh` の採用、またはJSでの高さ計算）が行われているか。

## 監査結果の出力形式
監査完了後は、以下のフォーマットで報告する：
・【合格項目（レスポンシブ対応が良好な点）】
・【重大リスク（横はみ出し・タップ不能などの致命的不具合）】
・【改善推奨（操作性・視認性をさらに高める提案）】
